\section{Evaluation}\label{sec:evaluation}

\subsection{Testability}\label{sec:testability}
The cloud system's testability is ensured through rigorous automated checks for
both infrastructure and application logic. Local \texttt{yarn} scripts automate
test execution and coverage reporting.

\subsubsection{AWS Infrastructure}
The AWS cloud infrastructure configuration is automatically validated using
built-in AWS Cloud Development Kit (CDK) assertions, leveraging the
\texttt{Template} and \texttt{Match} constructs. This ensures that the generated
resources and policies match the intended architectural design prior to deployment.

\subsubsection{AWS Lambda Handlers}
AWS Lambda functions are thoroughly unit-tested using Python's \texttt{unittest}
or \texttt{pytest} frameworks, employing exhaustive mocking to isolate execution
behavior. To evaluate Lambda handlers independently of the API Gateway, a locally
defined \texttt{TestEvent} JSON payload is utilized to replicate realistic
incoming requests during testing. Additionally, for runtime observance and
debugging in the deployed environment, Lambda function executions and errors
are continually logged to dedicated AWS CloudWatch log groups.

\subsubsection{Sensor Node Firmware}
Firmware unit testing utilizes the AUnit framework~\cite{aunit_testing_arduino}
to cover modules like sensor readings, data aggregation, configurations, and Wi-Fi. Exhaustive
MQTT mocking was omitted due to real-world deviations. Instead, the node
subscribes to an MQTT test topic during operation to directly verify connection
health and publish functionality.
